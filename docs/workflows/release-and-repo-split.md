# Release And Repo Split

This project should become the public tooling source of truth for AoE2 AI
scripting, not the place where one personal AI has to live forever.

## Repository Boundary

Recommended split:

- `aoe2-ai-lab`: public tooling repo. Owns the parser, linter, package
  validator, local reference inventories, generated Markdown docs, editor
  extension, tests, and release scripts.
- AI package repo: private or public gameplay AI repo. Owns actual `.ai`,
  `.per`, RMS fixtures, experiments, logs, build scripts, and game-specific
  notes.
- Community corpora: optional test data. Keep only redistributable AI packages
  or small fixtures in the tooling repo. Do not mix arbitrary downloaded AIs
  with the public release unless license/redistribution is clear.

The AI package repo can use this tooling through the editor extension and, for
CLI work, either a checked-out sibling `aoe2-ai-lab` repo or a future published
Python package.

## Shared Reference Data

The local docs and JSON inventories remain owned by `aoe2-ai-lab`:

- `docs/extracted/inventories/`
- `docs/reference/generated/`
- `extensions/aoe2-aiscript-cursor-local-lab/data/`

The editor extension bundles a runtime copy under:

```text
extensions/aoe2-aiscript-cursor-local-lab/lab/
```

That folder is generated by:

```powershell
npm run sync:extension-lab
```

Do not edit the bundled copy directly. Edit `src/`, `docs/extracted/`, or
`docs/reference/generated/`, then regenerate the bundle through the packaging
workflow.

## Extension Runtime Model

Marketplace users should not need to clone this repo just to get diagnostics.

Default behavior:

- Empty `aoe2_AiScript.labPath`: use the validator/reference runtime bundled
  in the installed extension.
- Explicit `aoe2_AiScript.labPath`: use that local development checkout. This
  is for contributors working directly on the parser or reference data.
- `aoe2_AiScript.pythonPath`: still points to the Python executable. Until the
  validator is ported to TypeScript or packaged with an embedded Python runtime,
  users need Python available on PATH or configured here.

Package reports generated from the extension are written to the workspace
`.tmp/lint-package` when using the bundled runtime. This keeps reports out of
the installed extension directory.

## Marketplace Checklist

Before publishing to either marketplace:

```powershell
npm run package:editor-extension
$env:PYTHONPATH='src'; python -m pytest tests -p no:cacheprovider
```

Then inspect the generated VSIX and test-install it in both editors:

```powershell
npm run install:vscode-extension
npm run install:cursor-extension
```

Publishing commands:

```powershell
npm run publish:vscode-extension
npm run publish:openvsx-extension
```

Requirements:

- Visual Studio Marketplace: create the `aoe2-ai-scripters` publisher, create an Azure DevOps
  personal access token, and authenticate `vsce`.
- Open VSX: create the `aoe2-ai-scripters` namespace and token for `ovsx`.
- Confirm `publisher`, `name`, `displayName`, `author`, `license`,
  `repository`, icon, README, and changelog are correct.
- Confirm third-party attribution from the original AoE2 AiScript extension is
  preserved.

Do not commit `.vsix` release artifacts. Attach the VSIX to GitHub Releases or
publish it through marketplace tooling.

## Longer-Term Cleanup

After the marketplace release path works:

- Publish `aoe2-ai-lab` as a Python package so CLI users can install it without
  cloning the full repo.
- Consider porting the validator core to TypeScript so the extension no longer
  depends on a local Python install.
- Move `extensions\aoe2-aiscript-cursor-local-lab\samples` and active experiment fixtures to a separate AI package repo once
  the tooling repo has stable release docs and tests.
